# Topos v0.3.0

## Before you install

Topos runs in Docker. You need Docker Desktop installed and running before starting the launcher.

- [Docker installation guide (English)](https://github.com/astrapi69/pluginforge-app-template/blob/main/docs/help/en/install/docker-desktop.md) - includes a "Is Docker safe to install?" section
- [Docker-Installationsanleitung (Deutsch)](https://github.com/astrapi69/pluginforge-app-template/blob/main/docs/help/de/install/docker-desktop.md) - mit Abschnitt "Ist Docker sicher zu installieren?"

The launcher detects Docker, downloads Topos automatically, and opens it in your browser. The first launch takes 5-10 minutes (Docker images build, ~2 GB disk space).

## Download

| Platform | File |
|----------|------|
| Windows | `topos-launcher.exe` |
| macOS (Apple silicon) | `topos-launcher-macos.zip` |
| Linux | `topos-launcher` (ELF binary) |

Each platform also ships a `*.sha256` checksum next to the binary.

## Running it on Linux and macOS

GitHub release assets carry no executable bit, so the Linux binary needs
one before it will start:

```bash
chmod +x topos-launcher
./topos-launcher --version   # prints the version, starts nothing
./topos-launcher             # starts Topos
```

On macOS the app is unsigned: open `topos-launcher-macos.zip`, then
right-click "Topos Launcher.app" and choose Open once to get past
Gatekeeper. Double-clicking the first time shows a refusal instead.

## Verifying downloads

```bash
# Linux
shasum -a 256 topos-launcher
cat topos-launcher.sha256

# macOS
shasum -a 256 topos-launcher-macos.zip
cat topos-launcher-macos.zip.sha256
```

```powershell
# Windows
Get-FileHash -Algorithm SHA256 .\topos-launcher.exe
Get-Content .\topos-launcher.exe.sha256
```

The hashes must match.

If your operating system warns about an unsigned binary, see the [Topos installation overview](https://github.com/astrapi69/pluginforge-app-template/blob/main/docs/help/en/installation.md).

## What's new

## [0.3.0] - 2026-08-13

The installability release. v0.2.0 made Topos work offline; this one
makes it feel like an app you install and trust - a lean install
footprint, a visible install prompt, a tree over the whole inventory,
and fixes for every wall an iPhone put up during real-world use.

### Added

#### Tree view of the whole inventory
- The Containers page gained a list/tree toggle. The tree shows the
  shape the Ordner-Ordnung workbook always had: groups (Meine Ordner,
  Ordner Eltern, Boxen, and any other type/owner combination the data
  contains) with their containers, and each container's entries as
  leaves - numbered `42-1`, `42-2`, with item counts per subtree.
- Built on `@astrapi69/tree-kit`; the category tree now uses the same
  library instead of a hand-rolled builder.

#### Install prompt where people can see it
- A dismissable app-level banner offers installation as soon as the
  browser reports it possible (Android Chrome, desktop Chromium). iOS
  already had its hint; the button in Settings > About stays as the
  second place. Dismissing sticks.

#### A fuller install contract
- The web manifest declares an explicit `id`, real screenshots (taken
  from the built app with seeded data), shortcuts to Container,
  Foto-Erfassung and Aktionen, a maskable icon in both densities, and
  no longer locks desktop installs to portrait.

#### Excel workbooks accepted in Settings
- Einstellungen > Import & Export now recognises a workbook by content
  (xlsx is a ZIP; four magic bytes decide) and runs the same idempotent
  import as the Import page - offline in the browser, over the API when
  a backend is there. JSON backups behave as before.

#### Copy button on the error dialog
- The bug-report dialog can copy the full report to the clipboard. On
  iOS the report text was unreachable before (unselectable preview),
  and the GitHub link was the only exit.

### Changed

- **bun replaces npm** as package manager and script runner for
  `frontend/` and `e2e/` (bun 1.3.14). Node 24 stays the runtime; the
  builds are byte-identical. Docker, CI, Makefile and docs moved in the
  same commit.
- Launcher answers `--version` / `-V` headlessly - the first way to
  check a built artifact without starting the GUI.
- Service-worker precache trimmed from 2.84 MB to 1.62 MB: the lazy
  exceljs chunk moved to a runtime cache (offline export still works
  after first use), 340 KB of unreferenced icons deleted, link-preview
  images excluded.

### Fixed

- iOS could not pick real files: the pickers filtered by file type, and
  iOS derives the type from the file NAME - a workbook that lost its
  extension in transit stayed greyed out with no error. Both pickers
  (Import page, Settings restore) now accept any file and validate the
  content instead, answering wrong files with a precise message.
- The excel-import plugin's 31 tests ran nowhere - `make test` skipped
  them and the CI plugin matrix was disabled with a stale
  "zero plugins" comment. They now run in the backend venv on every
  `make test` and every CI push.
- The CI pre-commit job lacked the tooling its own hooks need (eslint
  flat-config imports, PyYAML) and had been red for five runs.
- Release template: the Linux download is `topos-launcher` (not
  `topos-launcher-linux`), verify commands match the real asset names,
  and the template now says that GitHub strips the executable bit
  (`chmod +x` needed) and how to get past Gatekeeper on macOS.
